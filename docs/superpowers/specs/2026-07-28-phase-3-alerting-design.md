# Phase 3 告警与 Webhook 设计

## 目标

为 TinyProbe 增加持久化告警规则、告警事件和通用 Webhook 通知。告警从实时指标与离线状态异步评估，Webhook 的失败或重试不得影响 Agent 上报。

## 已确认范围

- 支持离线、CPU 使用率、内存使用率、磁盘使用率、磁盘可用空间五类规则。
- 资源规则默认持续 5 分钟；离线规则沿用实时存储已有的 30 秒离线判定，触发时长固定为零。
- 每个告警周期发送一次触发通知和一次恢复通知；可选重复通知默认关闭。
- Webhook 是唯一通知通道，支持 URL、开关、自定义请求头、JSON 正文模板、测试发送和三次递增延迟重试。
- 管理 API 均要求已登录管理员会话；不提供邮件、即时通信、签名、多用户路由或远程操作。
- 不新建“配置”页面。新增一个“告警”页面，页面内依次呈现规则管理、事件历史和 Webhook 通知设置。
- 视觉设计复用现有概览、服务器管理页的排版、控件、响应式断点和无障碍样式。
- Phase 3 的测试与构建命令统一在全部实现完成后执行；实现期间不运行测试命令。

## 后端架构

`migrations/003_alerting.sql` 创建以下表：

- `webhook_configs`：单例 Webhook 设置。
- `alert_rules`：按服务器定义的启用状态、指标、比较条件、阈值、持续时长和重复间隔。
- `alert_states`：每条规则的 `normal`、`pending`、`firing` 或 `recovered` 持久状态。
- `alert_events`：触发与恢复事件，按最新优先查询。
- `webhook_attempts`：每次事件投递或测试投递的结果。

新增 `internal/alerting` 包。纯状态机不访问数据库、网络或时钟；它只基于传入的规则状态、当前数值、是否越界和时间返回下一状态及是否应通知。异步评估器订阅实时 `snapshot.updated` 与 `snapshot.offline` 事件，在容量受限的队列中顺序处理。队列满时上报请求立即返回，并调度依据最新快照的补偿评估。

指标计算规则如下：内存使用率为 `used / total * 100`，总量为零时为零；磁盘使用率使用所有磁盘中的最大值；可用空间使用最小值。百分比和离线仅允许 `gt`，磁盘可用空间仅允许 `lt`。

投递器使用两个后台 worker 和容量 64 的队列。它用 `text/template` 渲染正文，提供 JSON 转义函数，要求最终正文为合法 JSON。请求为 `POST`，10 秒超时，只有 2xx 成功；失败分别在 0 秒、5 秒和 15 秒进行至多三次尝试，并持久化每次结果。投递排队失败只记录日志，绝不向 Agent 上报路径传播错误。

## HTTP API

在管理员认证组中提供：

- `GET`、`POST /api/alert-rules`
- `PATCH`、`DELETE /api/alert-rules/{id}`
- `GET /api/alert-events`
- `GET`、`PUT /api/webhook`
- `POST /api/webhook/test`

资源规则的持续时间默认 300 秒，允许 0–86400 秒；离线规则强制阈值零和持续时间零。重复间隔默认零，启用时允许 300–604800 秒。Webhook 响应中掩码名称含 `authorization`、`token`、`secret` 或 `key` 的请求头值；带掩码的更新请求保留原始密钥。

## 告警页面

新增 `/alerts` 路由，并在主导航中增加“告警”。页面从上到下包括：

1. 规则管理：内联新建与编辑表单；列表显示服务器、可读条件、当前状态、启用开关、编辑与带内联确认的删除操作。
2. 事件历史：最新优先显示状态、服务器、指标、数值、阈值、起止时间和投递结果；展开行展示最多三次的投递尝试。
3. Webhook 通知：URL、启用开关、可编辑请求头、JSON 模板、可用变量说明和“发送测试”按钮。测试结果显示最终状态码，或失败摘要及尝试次数。

移动端保留字段标签；表格转为堆叠的事件行。所有操作保留表单值并在接口错误后显示就近错误信息。秘密请求头不会在重新加载后显示原文。

## 生命周期与验证

应用创建时装配 Repository、投递器和评估器；应用后台生命周期负责启动和停止它们。服务器删除依赖外键级联删除对应规则、状态与事件。

实现完成后统一运行 Go 单元与集成测试、前端测试、lint、生产构建以及 Docker Compose 健康检查。验收覆盖 CPU/磁盘/离线与恢复事件、三次 Webhook 重试、失败投递不阻塞 `204` Agent 上报、规则与 Webhook 管理界面及移动端呈现。
