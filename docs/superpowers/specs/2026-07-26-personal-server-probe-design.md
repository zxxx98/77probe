# 个人服务器探针应用设计规格

- 日期：2026-07-26
- 状态：已完成方案确认，等待书面规格复核
- 产品形态：个人自托管、单用户、只读服务器监控

## 1. 产品定位

本产品是一套面向个人用户的轻量服务器探针系统，用于集中查看 1–10 台 Linux 服务器的实时资源状态、历史趋势和基础告警。

产品强调以下原则：

1. 部署简单：服务端通过 Docker Compose 启动。
2. 探针轻量：Agent 仅执行只读采集，不提供远程控制能力。
3. 信息直接：首页优先显示异常机器和当前风险。
4. 告警克制：只使用通用 Webhook，提供去重、恢复通知和失败重试。
5. 范围明确：不向多租户、企业权限或综合运维平台扩张。

## 2. 目标用户与成功标准

目标用户是维护少量 VPS、云服务器或家庭服务器的个人开发者。典型使用方式是在一台自有服务器上部署监控服务，再在其他 Linux 主机安装 Agent。

首版成功标准：

- 最多 10 台服务器以 5 秒周期持续上报时，系统稳定运行。
- 实时数据从采集到页面展示不超过 10 秒。
- Agent 常驻内存目标不超过 30 MB。
- 停止上报后约 30–45 秒判定离线并触发 Webhook。
- CPU、内存和磁盘规则能正确处理持续时间、告警恢复和防重复。
- 30 天历史指标受到固定保留策略约束，数据库不会无限增长。
- Docker Compose 能完成首次启动、重启和版本升级。

## 3. 首版功能范围

### 3.1 服务器管理

- 添加、重命名、停用和删除服务器。
- 为每台服务器生成独立 Agent Token。
- Token 创建后仅完整展示一次；可单独撤销和重新生成。
- 根据服务器架构生成 Agent 安装命令和基础配置。
- 展示 Agent 版本、最后上报时间和在线状态。

### 3.2 基础信息

每台服务器展示以下信息：

- 主机名
- Linux 发行版和版本
- 内核版本
- CPU 型号与核心数
- 系统架构
- IP 地址
- 启动时间与运行时长
- Agent 版本

### 3.3 实时指标

首版采集并展示：

- CPU 使用率
- 1、5、15 分钟系统负载
- 内存总量、已使用量和使用率
- Swap 总量、已使用量和使用率
- 磁盘总量、已使用量、使用率和剩余空间
- 磁盘读取与写入速率
- 网络上传与下载速率
- 网络累计上传与下载量
- 系统运行时长

首版不采集进程详情、TCP/UDP 连接详情、容器内部指标和硬件温度。

### 3.4 仪表盘

- 服务器总数、在线数量、离线数量和异常数量。
- 当前总体网络速率与累计流量概览。
- 一屏展示全部 1–10 台服务器。
- 每行展示状态、系统、运行时长、CPU、内存、磁盘和网络。
- 异常服务器自动排在正常服务器之前。
- 数据每 5 秒刷新，不要求用户手动刷新页面。

### 3.5 服务器详情

- 当前在线状态与最后上报时间。
- 完整系统基础信息。
- CPU、负载、内存、Swap、磁盘和网络当前值。
- 实时、1 天、7 天和 30 天时间范围切换。
- 资源趋势图与当前告警列表。
- 页面不出现重启、命令执行、终端或文件管理入口。

### 3.6 历史趋势

- Agent 每 5 秒上报实时数据。
- 服务端将实时值保存在内存中，并按 1 分钟聚合后写入 SQLite。
- 聚合值至少包含平均值和最大值，以支持趋势判断和峰值查看。
- 历史指标固定保留最近 30 天，后台自动删除更早数据。
- 不提供备份、导出、手动清理或保留周期设置页面。

### 3.7 告警

首版支持以下规则：

- 服务器离线
- CPU 使用率超过阈值
- 内存使用率超过阈值
- 磁盘使用率超过阈值
- 磁盘剩余空间低于阈值

资源类告警必须持续超过配置时长才会触发，默认持续时间为 5 分钟。告警状态机包含：

1. `normal`：指标正常。
2. `pending`：已超过阈值，但尚未满足持续时间。
3. `firing`：持续时间满足，触发一次异常 Webhook。
4. `recovered`：指标恢复，触发一次恢复 Webhook，随后回到 `normal`。

同一告警持续期间默认不重复通知。可以配置重复提醒间隔，但默认关闭。

### 3.8 Webhook

通知渠道仅支持通用 Webhook，不内置邮件、Telegram、企业微信、钉钉或飞书适配器。

Webhook 配置包含：

- 请求 URL
- 自定义请求头
- JSON 请求体模板
- 模板变量占位符
- 发送测试功能
- 启用和停用状态

可用模板变量至少包含服务器名称、告警类型、当前值、阈值、开始时间、状态和详情页地址。

发送失败时最多重试 3 次，采用递增间隔。最终失败会记录在告警事件中，并在管理页面展示。

### 3.9 安全能力

- 仅支持一个管理员账户。
- 管理员密码使用安全密码哈希保存。
- 登录会话使用 HttpOnly、SameSite Cookie。
- Agent 使用每台服务器独立的 Bearer Token 上报。
- 服务端只保存不可逆的 Agent Token 摘要。
- 管理后台与 Agent API 默认同源，不开放宽泛 CORS。

首版明确不包含登录限速功能，也不编写 HTTPS 部署说明。

### 3.10 响应式界面

- 桌面端优先展示完整横向服务器指标。
- 平板端隐藏次要累计字段。
- 手机端保留服务器状态、CPU、内存、磁盘和当前网络等核心信息。
- 不开发原生移动应用。

## 4. 后续阶段候选功能

以下功能不进入首版，可在核心链路稳定后再评估：

- 服务器标签与分组
- CPU 或内存占用最高的进程列表，仅查看不可操作
- 温度、inode、TCP/UDP 连接数和容器数量
- 自定义仪表盘排序
- Webhook HMAC 签名
- 深色模式
- 更多历史聚合粒度

## 5. 明确不做

- Web 终端和远程命令
- 文件管理
- 远程重启和进程操作
- 网站、API、HTTP 或 TCP 拨测
- 公开状态页
- 多用户、多租户和权限角色
- 计费、配额和开放注册
- 邮件与内置第三方通知渠道
- 企业级审计、高可用和集群部署
- Windows、macOS 和 FreeBSD Agent

## 6. 系统架构

### 6.1 Agent

Agent 使用 Go 编写，首版发布 Linux `amd64` 和 `arm64` 静态二进制。

职责：

- 从 `/proc`、`/sys` 和操作系统接口读取指标。
- 每 5 秒向服务端主动上报。
- 使用独立 Token 完成身份认证。
- 上报失败时退避重试，最长间隔 60 秒。
- 网络恢复后立即恢复上报。

Agent 不开放入站端口，不接受服务端命令，不缓存或补传断网期间的历史指标。安装系统服务时可以使用管理员权限，但正常采集进程应尽可能以低权限运行。

### 6.2 服务端单体应用

服务端包含以下内部模块：

- 管理员认证
- 服务器与 Token 管理
- Agent 指标接收 API
- 当前状态缓存
- 分钟级聚合写入
- 在线状态判断
- 告警规则引擎
- Webhook 发送与重试
- 管理后台 API
- SSE 实时事件推送
- 前端静态资源托管

这些模块部署在同一个应用容器中，不引入 Redis、消息队列或独立任务服务。

### 6.3 数据库

使用 SQLite 并开启 WAL 模式。数据库文件通过 Docker 数据卷持久化。

核心表：

- `admins`：管理员账户与密码摘要
- `servers`：服务器配置、Token 摘要、启停状态
- `metric_minutes`：分钟级历史聚合指标
- `alert_rules`：告警规则
- `alert_events`：告警状态变化和通知结果
- `webhook_configs`：Webhook 地址、请求头和模板
- `schema_migrations`：数据库版本

当前 5 秒级指标只保留在内存，不保存为原始历史数据。服务端重启后，当前状态等待 Agent 下一次上报恢复。

### 6.4 Web 管理界面

浏览器使用普通 HTTP API 完成管理操作，使用 SSE 接收实时状态变化。当前规模不需要为浏览器实时展示引入双向 WebSocket。

## 7. 数据流

1. Agent 读取系统指标并构造带采集时间的上报数据。
2. Agent 使用独立 Token 调用指标接收 API。
3. 服务端完成 Token 校验、字段校验和服务器状态更新。
4. 最新指标写入内存，并通过 SSE 通知已登录浏览器。
5. 聚合模块按分钟计算平均值和最大值并写入 SQLite。
6. 告警引擎根据最新指标更新规则状态机。
7. 告警进入 `firing` 或 `recovered` 时创建事件并发送 Webhook。
8. 后台任务删除超过 30 天的历史指标。

服务器在线状态以服务端最后接收时间为准，避免 Agent 系统时间不准确影响离线判断。连续约 30 秒没有收到上报时判定离线。

## 8. 异常处理

### 8.1 Agent 上报失败

- 请求超时后进入退避重试。
- 不阻塞下一次本地指标采集。
- 不在本地落盘积压历史数据。
- 恢复连接后发送最新状态，不补传旧数据。

### 8.2 数据库写入失败

- 当前实时状态仍保留在内存并继续更新。
- 历史写入错误记录到服务端日志。
- 管理界面显示系统异常提示。
- 告警状态写入失败时不伪造发送成功记录。

### 8.3 Webhook 失败

- 记录 HTTP 状态码或网络错误摘要。
- 最多重试 3 次。
- 最终失败状态保留在告警事件中。
- Webhook 失败不影响指标接收和其他告警计算。

### 8.4 数据缺失

- 历史图表明确显示数据空洞，不使用前一个值伪造连续数据。
- 当前状态过期后显示离线，不继续展示为正常实时值。

## 9. UI 设计方向

界面参考用户提供的监控面板风格，但不直接复制。整体氛围定义为：个人在明亮的家庭工作环境中查看服务器，希望快速确认一切安稳，而不是面对冰冷的企业 NOC 控制台。

视觉原则：

- 使用纯白页面背景，通过品牌色、状态色和文案表达温度，不使用米黄或泛灰纸张背景。
- 使用克制的深玫红作为品牌色，仅用于当前导航、重点操作和少量装饰。
- 在线状态使用绿色，警告使用橙色，故障使用红色。
- 面板和服务器状态行使用 12–14px 圆角。
- 卡片优先使用轻量短阴影，不同时叠加明显边框和大范围阴影。
- 顶部采用轻量导航，不设置沉重的深色侧边栏。
- 使用友好但克制的文案，例如“服务器们都很安稳”。
- 每个页面最多保留一处轻量个性元素，不用装饰干扰数据阅读。
- 数据文本使用统一无衬线字体和等宽数字特性。
- 动效只表达状态变化，持续 150–250ms，并支持减少动态效果偏好。

仪表盘布局：

- 顶部品牌、导航和当前总体状态。
- 服务器总数、在线数量、异常数量组合成连续概览区。
- 网络概览使用轻微品牌色表面，与核心状态区形成节奏变化。
- 服务器使用横向状态行，避免大量完全相同的独立卡片。
- 异常机器排在首位，并通过语义状态色强调具体风险指标。

服务器详情布局：

- 顶部展示返回入口、服务器名称、在线状态和最后上报时间。
- 系统信息以紧凑字段区呈现。
- 指标区域先显示当前值，再显示实时、1 天、7 天和 30 天趋势。
- 页面只提供查看与时间范围切换，不出现远程操作控件。

## 10. 测试策略

### 10.1 Agent 测试

- `/proc` 和 `/sys` 数据解析单元测试
- CPU、内存、磁盘和网络速率计算测试
- 不同 Linux 发行版与缺失字段兼容测试
- 上报超时和退避重试测试
- `amd64`、`arm64` 构建测试

### 10.2 服务端测试

- 管理员认证与会话测试
- Agent Token 创建、校验、撤销和重置测试
- 指标载荷校验测试
- 在线与离线状态转换测试
- 分钟聚合和 30 天删除测试
- 告警状态机测试
- Webhook 模板、测试发送、重试和恢复通知测试
- SQLite 迁移和重启恢复测试

### 10.3 前端测试

- 登录、仪表盘、服务器详情、告警和设置基础流程
- 在线、离线、等待告警、告警中和恢复状态展示
- 无历史数据、历史数据空洞和系统异常状态
- 桌面、平板和手机响应式布局
- 键盘焦点、颜色对比和减少动态效果设置

### 10.4 集成与负载验证

- Docker Compose 首次启动与重启冒烟测试
- 模拟 10 个 Agent 每 5 秒持续上报
- 验证实时展示延迟、离线告警时间和数据库增长速度
- 验证 Webhook 服务不可用时不会阻塞指标接收

## 11. 首版交付顺序

1. Agent 基础指标采集与上报协议。
2. 服务端 Token 鉴权、指标接收与当前状态。
3. 管理员登录、服务器管理和基础仪表盘。
4. 分钟级历史聚合与趋势图。
5. 告警状态机和 Webhook。
6. Docker Compose、数据库迁移和完整验证。

此顺序只描述产品依赖关系；具体开发任务和文件拆分将在用户复核本规格后通过实施计划确定。
